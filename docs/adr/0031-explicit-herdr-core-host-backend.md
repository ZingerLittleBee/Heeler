# Select herdr-core explicitly on a Host

Issue [#535](https://github.com/ZingerLittleBee/Heeler/issues/535) reports desktop Agents missing while the legacy herdr connection succeeds. herdr-app uses a separate core with a different protocol; changing the legacy socket path cannot reach its inventory correctly.

`Host.backend` selects herdr or herdr-core and defaults existing catalogs to herdr. Core uses generation-one JSON-RPC through a verified core executable's `connect` command and live PTYs through its `attach` command, on the existing authenticated SSH connection. Each invocation selects `HC_SESSION`; no legacy operation falls back to core, and unsupported core operations never reach legacy herdr. Session validation follows the selected backend's grammar. Pairing Code v2 continues to describe only a legacy Herdr Endpoint; editing or duplicating it preserves that endpoint. Core requires a new manual Host with an existing SSH authentication method.

Core terminal addresses remain opaque identifiers. Each local terminal supplies one Pane and Tab, grouped into a Workspace by launch directory. Unnamed Tabs have empty labels so terminal titles remain visible. This grouping does not edit or interpret the desktop's layout documents, and phone-created terminals are not automatically placed in that layout. Federated terminals are omitted because their directories and files do not belong to this SSH Host; users add their owning machine directly. Recognized program identities supply Agents. A positively identified plain foreground shell overrides a stale Agent report, while unavailable foreground data and command wrappers do not establish that an Agent exited. Error remains distinct from Blocked but receives attention styling and ordering.

Subscription acknowledgement precedes the Console snapshot. A core stream already contains all terminal events, so inventory changes do not replace its subscription. Sequence cursors reject older delivered events; heartbeat global sequence values do not advance the delivery cursor, and missed events trigger fresh inventory. Title events update local presentation without snapshot or snippet requests, preserving newer deltas across in-flight snapshots. Repeated root status reports with the same state, app and title do not cause another refresh; changes to those fields still converge through a snapshot.

Generation-one `terminal.send` queues input without binding it to the Agent process that a client inspected, and disconnecting does not cancel the queued action. A preflight cannot prevent an Agent from returning to a shell before delivery. Heeler therefore disables `promptAgent` for core. Composer instead offers explicit single-line, control-free insertion into an already live Attach, without Enter; the user checks the terminal and submits there. Multiline drafts stay local for the existing reviewed Paste flow. An uncertain dispatched core mutation is never automatically replayed; a failure before dispatch can retain normal connection recovery. Screen previews use `terminal.read` with `lines: 0` because positive history can scroll a full-screen program and hold viewer input/output while restoring it.

The official `attach` CLI is an intentional compatibility boundary: it consumes its configured detach chord (default Ctrl+backslash) and has no literal-chord escape in core 0.1.13. The guide discloses this limitation. Transparent delivery of that chord would require upstream support or a separate framed attachment implementation. Similarly, `connect` can auto-start an empty selected session; success is not proof that the desktop uses that session.

Plugin-based notifications, Live Activities and Usage are unavailable. A legacy Host must finish turning off its notification registration before changing to core. Chat is unavailable without exact conversation identity. Rename and Worktree actions are hidden or refused because core does not implement their legacy contract. SSH file operations remain shared. Core uses the same combined exec-session limit as native Windows because its event channel consumes an OpenSSH session slot too. Agent launches carry the executable probe's resolved PATH so a separately running daemon can find that executable's runtime dependencies without copying unrelated SSH environment values.

See the [setup guide](../guides/herdr-core.md) for the user contract and the [versioned observations](../agents/herdr-compatibility.md) for release-specific evidence. The codec and real-SSH regression suites target generation one independently of desktop layout; test execution evidence belongs to the reviewed candidate, not this decision record.
