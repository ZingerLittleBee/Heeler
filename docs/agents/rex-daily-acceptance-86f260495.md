# Rex daily workflow acceptance

The integrated application is **D = 86f2604950d65f4784f6b10c56abd253ba3d69e1**. It includes the cross-platform daily-work implementation, the macOS socket diagnostic, the Linux process reader, bound Antigravity text on Linux, read-only Amp on Linux and wrapped Devin plan recognition. The original source baseline is origin/main `10148154331e5496afaef9b5b450d514fd1d7d8e`. Herdr created the clean delivery worktree from that commit. The reference app is Heeler 0.1.18 (43) on Herdr TUI 0.9.5, protocol 22. The Rex Hosts ran 0.1.0-preview.25 (`b070aae645f5`, advertised API 24). The app negotiated revision 19. Independent clients also exercised revision 12. Host systems were macOS 27.0.1 (26A434) arm64 and Debian 12.15 on arm64 Linux 7.2.12-orbstack. The iPhone and iPad Simulators ran 27.0 (24A434) with Xcode 27.2 (27B52).

Each cell combines a user capability and a verification result. **N** means native, **R** read-only, **T** terminal-only, and **U** unavailable. **PASS** and **FAIL** refer to the scenario on D in the Rex columns. **NOT-RUN** means it lacks a qualifying run on D. **N/A** gives its reason in the cell. In the reference column, a named reference run was observed in the original pinned baseline or the separately frozen first candidate. Both results are exposed where an initial attempt failed and a fresh test passed. A terminal-only pass establishes a working terminal route. Native Windows had no test Host. A true macOS login with only Rex visible and a separate Debian container with only Rex installed are identified explicitly. Other Host tests used isolated SSH accounts with both reference and Rex servers.

### Remaining boundaries

Rex revisions 12–19 lack a conditional destructive operation against the current foreground epoch. The server ignored an expected-foreground field and closed a different process; moving a block could also change desktop focus. Cross-session transfer requires revision 22. These native actions stay gated. The supported user route for ending a shell is its visible Terminal. An empty Rex session can remain after the last shell exits. [Real protocol observations and upstream requirements](rex-object-operations.md)

Heeler rechecks the current server, block, foreground program, session and prompt or turn before an effect. It serializes its own inputs. A desktop participant could still act after the final read and before the server applies a key. A server-side conditional write would close that interval. Unknown status limits native Stop and Blocked Cards. The targeted Terminal remains available. [Chat behavior and stale input](rex-chat-parity.md)

Rex-only usage, background push and the Lock Screen need a persistent publisher, registration and delivery. The per-device foreground banner consumes connected Rex status and the configured preference. A private Herdr relay establishes encrypted delivery to that relay. It does not exercise physical APNs or ActivityKit. [Host integrations and installation scope](rex-host-services-parity.md)
