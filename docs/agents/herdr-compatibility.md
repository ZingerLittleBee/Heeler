# herdr compatibility observations

Consult this reference for RPC framing, protocol negotiation, subscription
recovery, Agent launch/input, terminal attach, or remote scrolling behavior.
These observations were moved from `CLAUDE.md` without changing their evidence
versions. They are historical evidence, not fresh tests on the installed herdr.

## Current routing

- Unix API and Events use direct-streamlocal; Unix terminals use PTY exec
  ([ADR 0011](../adr/0011-libssh2-direct-streamlocal-transport.md)). Native
  Windows uses `remote-api-bridge` and `terminal session control`
  ([ADR 0018](../adr/0018-native-windows-hosts.md)); Unix forwarding refusal
  never selects the Windows path.
- herdr-core Hosts are a Server Kind of their own, never a fallback for a
  Herdr TUI Host. Each carries one framed connection to its core:
  direct-streamlocal on Unix, `herdr-core connect` over SSH exec on native
  Windows, and connecting never starts a core
  ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)).
  Their Agents fill the Console's Herdr TUI-shaped models
  ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md)).
- Initial API request timeout, herdr 0.9.5 (`INITIAL_REQUEST_TIMEOUT` in
  `src/api/server.rs`, source review): an accepted API socket closes after five
  seconds without a request line. In a #523 Simulator/Instabox test against
  herdr `2713feb56`, blocking SSH downlink for 18 seconds delayed the
  channel-open acknowledgement past that timeout. Recovery produced EOF before
  a response line, with `timed out reading api request` in the server log. This
  is a retryable channel failure, not evidence of an incompatible response;
  complete invalid JSON and oversized responses remain protocol errors. Recovery
  must not replay an operation that changes Host state.
- Start with [HeelerSSHTransport](../../Sources/Heeler/Transport/HeelerSSHTransport.swift)
  and [EventsSession](../../Sources/Heeler/Transport/EventsSession.swift) for
  current adapters and recovery. Older symbol names below belong to their
  observation's version; use the [source map](navigation.md) to reach current owners.
- The committed schema is [scripts/herdr-schema.json](../../scripts/herdr-schema.json).
  Generated types describe that snapshot, not every method in every herdr release.
- For native Windows setup or runtime acceptance, use the
  [setup guide](../guides/windows-setup.md) or
  [acceptance checklist](../guides/native-windows-testing.md).
- Chat ([ADR 0024](../adr/0024-native-chat-from-agent-transcripts.md)) reads
  transcripts over SFTP, and OpenCode's session store with a read-only exec
  ([ADR 0025](../adr/0025-opencode-chat-reads-its-session-store.md)), never
  through herdr. herdr supplies the session id, Agent Status, screen reads,
  `agent.prompt`, `agent.send_keys` and `pane.send_input`. For Codex, Chat
  also reads `pane.process_info` arguments and stats the shared server's
  control socket, `~/.codex/app-server-control/app-server-control.sock`, to
  warn when Codex runs on that server (`CodexLaunch`).

## Versioned observations

- OpenCode's TUI plugin list, OpenCode 1.19.5, 2.0.32 and 2.2.5 (2026-11-02, source review of `anomalyco/opencode` at those tags, not run; 2.0.32's `cli.json` ran on a Mac, and 1.19.5's `tui.json` and 2.2.2's `cli.json` on hc-lab through the lab's [OpenCode edit](../guides/herdr-core-testing.md#opencode-edit), both below, and 2.2.5 has not run): the global config directory is `$XDG_CONFIG_HOME/opencode` or `~/.config/opencode`, on macOS too, and OpenCode creates it at start. 1.x reads `tui.json` then `tui.jsonc`, as JSONC, and adds up `plugin` across them; a root `tui` key is flattened over by a top-level `plugin`, so Heeler refuses a file with one and says to add the entry inside `tui`. A path entry resolves against the config file, needs a `package.json` or an index file in the folder, and a default export with `id` and `tui()`. 2.x reads only `cli.json`, JSONC, with `plugins`, relative paths included; a folder resolves by its conventional root names, `tui` here, and 2.2.5 takes `package.json` only if it has both `name` and `exports`, which Heeler's has neither of. `cli.json` is created by migration only when absent, at OpenCode's start by this reading, though a running 2.2.2 on hc-lab also did it while Heeler's removal ran (below). 1.x's store has `session`, `message`, `part`, `todo` and `session_message`, and no `session_v2`, the table Chat then read; Chat now reads 2.x from `session_v2` and 1.x from `session`, `message` and `part` (ADR 0025).

- Frames through `herdr-core connect` (method above; a Node client spoke the same script to `connect` as a child process and directly to the pipe, and the outcomes below were the same on both, though frame counts and reply lengths differed slightly): this run was local, and the crossing is in the SSH exec observations below. The missing ones include 0x1A (Ctrl+Z), and among the frames recorded through `connect` that low byte appears once, in a separate run's 26-byte attach DATA frame. CREDIT frames for foreign channels carrying all byte values left the link in sync. `connect`'s stderr stayed empty and it exited 0. A `terminal.put` of 6 MiB, in one frame whose base64 alone is 8 MiB, arrived with the same hash. A 3,145,740-byte attach DATA frame of text reached a raw-mode program with the same hash, in about 40 seconds (about 80 KB/s; what sets that rate was not measured), and the link stayed up. With credit withheld a program wrote 6,389,760 bytes (about 6.09 MiB, 98,304 lines of 65 bytes) and a last line: 261,859 bytes came before credit, then 2,195,978 bytes in total with one `CSI 2J`, 33,778 lines, the first and last lines present, two gaps, no close, and a live link. - Subscription overflow, herdr 0.9.2 and later (source review of `src/api/subscriptions.rs` `subscription_events_after` and `src/api/event_hub.rs` at `v0.9.2` and `v0.9.4`, absent at `v0.9.1`; herdr's socket API documentation at `v0.9.4`; release note #4178, #4225; not reproduced live): every subscription reads one shared history of the last 512 events, and a subscriber that falls behind it gets one error line carrying its `events.subscribe` request id, `code: "events_lost"` and "event subscription fell behind retained history; resubscribe and resync with session.snapshot", after which herdr closes that connection. - Windows named-pipe access, herdr 0.9.4 (source review of `src/platform/windows.rs` `local_server_security_descriptor` and `local_server_connection_error`, `src/ipc.rs` `bind_local_listener`, `src/cli/server.rs` and `src/server/headless/bootstrap.rs` at `v0.9.4`, and of herdr's `windows-beta` documentation at `v0.9.4`; release note #4717, #4769, #4777, #4779; not exercised on a native Windows Host): a server's named pipes grant SYSTEM full access and the server's own account read and write, and nobody else. When the server's token is elevated, a High integrity label also refuses that account's ordinary (medium-integrity) processes, so only administrator terminals can connect; herdr's documentation notes that this includes a server started through an elevated SSH login. A server started with `herdr [--session <name>] server --allow-unelevated-clients`, or while herdr's config sets `[server] allow_unelevated_clients = true`, uses a Medium label and admits both. The setting is read when the server starts, so reloading config does not change a running server, and other accounts stay excluded. A refused client's error begins "For an elevated server, use an administrator terminal" and names the flag, and `herdr session list` reports the session with `connection_error` (see the unreachable sessions bullet above). The [Windows setup guide](../guides/windows-setup.md) therefore leaves the scheduled task's highest privileges cleared and starts the named session from a normal terminal.
