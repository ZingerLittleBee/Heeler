## Details moved from the user guide (2026-11-06)

### Host persistence, detection, and connection

- **Saved Host catalog failure:** [HostStore](../../Sources/Heeler/Hosts/HostStore.swift) stores herdr-core Hosts in a separate defaults catalog (`herdrCoreHosts`). If Heeler cannot decode that catalog on launch, the **Hosts** tab shows an error banner, Herdr TUI Hosts continue working, the raw saved data is left untouched, and no herdr-core Host can be added until the catalog reads again.
- **Fixed Server Kind and session validation:** A Host added by hand stays unconfirmed until the user confirms **Use herdr-core** or **Use Herdr TUI** once; after confirmation, neither reconnects nor edits switch its kind ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)). A session name that `hc` refuses, or one outside native Windows' allowed characters (`[A-Za-z0-9._-]`, not starting with `-`), leaves the Host unconfirmed and displays the reason.
- **Stale socket vs refused forwarding:** On Unix, `core.lock` and a socket file left behind after a core crash or `SIGKILL` produce the same SSH `direct-streamlocal` failure as an SSH server with `AllowStreamLocalForwarding` disabled, so Heeler names both causes when a socket file exists at the path ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)).
- **Socket path length:** When a session name pushes the Unix socket path past 107 bytes on Linux or 103 bytes on macOS ([HerdrCoreLocator](../../Sources/Heeler/Transport/HerdrCore/HerdrCoreLocator.swift)), the Host reads **The herdr-core socket path is too long** ([lab checklist](../guides/herdr-core-testing.md#connect-states)).
- **Linux Start race:** If a core starts on the Host between preflight and **Start herdr-core**, `server start` exits 0 without replacing the process. Heeler compares the reported uptime against the command dispatch and shows **herdr-core was already running** and that **Start changed nothing**, without claiming the interactive login shell's environment ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md), [lab checklist](../guides/herdr-core-testing.md#start)).
- **Windows autostart window:** On native Windows, Heeler checks the named pipe with PowerShell before running `herdr-core.exe connect --session <s>`. Because `connect` itself calls `connect_or_start`, a core that stops in the single round trip between the pipe check and `connect` is started by `connect` ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)).

### Console organization, Agent status, and Harness Edits

- **Derived and child placement:** A Terminal without `herdr.space` / `herdr.tab` labels that was started from inside another Terminal (`parent` set) joins its parent's Workspace and Tab as another Pane; any other unlabeled Terminal joins a derived Workspace named for its first-seen launch directory ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md), [HerdrCoreOrganization](../../Sources/Heeler/Console/HerdrCoreOrganization.swift)).
- **Windows `-NoExit` wrapper exit detection:** The Herdr desktop app on Windows starts agents under `powershell.exe -NoExit -Command "& '<program>'"`. Because the pseudo console keeps `powershell.exe` as the foreground process after the agent exits, Heeler moves such a Terminal from **Agents** to **Terminals** when its Terminal title reverts to the `powershell.exe` executable path ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md)). An agent under `-NoExit` that never sets its own terminal title may remain listed as an Agent after exit.
- **Minimum status-reporting releases:** [HerdrCoreStatusExplanation](../../Sources/Heeler/Console/HerdrCoreStatusExplanation.swift) names the first release known to report OSC 7501 Program Status: Claude Code 2.1.295, Codex 0.163, OpenCode 2.1, Pi 1.1.0 (older Pi releases report through the Host Helper extension), Oh My Pi 18.8.7, and Antigravity CLI 1.4.0 (reports as `app=antigravity`; the release comes from the changelog embedded in agy 1.5.3, not from a run of 1.4.0). No minimum release is recorded for Grok Build or unrecognized programs. A Terminal that reported `state=clear` reads as not having reported a state yet.
- **Done per-device turn transitions:** A turn finishes when an Agent transitions from **Working** to `done`. A transition from **Working** to `idle` finishes a turn only for programs not known to report `done`; Claude Code, Codex, Grok Build, Pi, and Oh My Pi are known to report `done`, so a Codex release too old to report `done` never shows **Done** ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md), [HerdrCoreTurnState](../../Sources/Heeler/Console/HerdrCoreTurnState.swift)).
- **Grok Build status edit (`GrokBuildProgramStatusEdit`):** Offered from the **Unknown** status sheet on macOS and Linux when Grok Build has not reported a status (for example under a leaked `TMUX`). Uses compare-and-swap over SFTP (`HostServices.replaceHostTextFile`) to set `program_status = "on"` under `[ui.notifications]` in `$GROK_HOME/config.toml` or `~/.grok/config.toml`. Refuses to write if the file changed after reading, if the Agent's environment cannot be read to resolve `GROK_HOME`, or if the TOML section cannot be edited unambiguously. Edits are tracked per file on the device that applied them and listed under **Harness Edits** in Host detail; if the file was modified after the edit, **Undo** refuses to overwrite it and offers **Stop Listing** ([HarnessConfigEditViews](../../Sources/Heeler/Console/HarnessConfigEditViews.swift), [lab checklist](../guides/herdr-core-testing.md#grok-build-edit)). Managed configs or `GROK_CONFIG` overlays can still override the file.
- **Agent List Fields and Pins:** On a core Host, **Settings > Agent List Fields** starts from Heeler's default fields, offers the Host's Terminal labels, and omits **Sync from plugin** ([AgentListFieldsEditor](../../Sources/Heeler/Settings/AgentListFieldsEditor.swift)). Pins are keyed by Host and survive core restarts; if the core's state directory is wiped and a new `core.id` starts at the socket, all Pins for that Host are cleared ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)).

### Terminals, Composer Send and Stop, launches, and Worktrees

- **Channel multiplexing and retention:** Live terminals attach as channels on the Host's single framed link, with up to five idle terminals retained for five minutes ([ADR 0017](../adr/0017-workspace-terminal-inventory-and-retention.md), [ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)). **Send** and **Add** appear once the connection reports the Host's platform.
- **Two-step Composer Send:** [HerdrCoreComposerSend](../../Sources/Heeler/Console/HerdrCoreComposerSend.swift) pastes the draft in bracketed paste mode, waits at least 550 ms for a fresh foreground sample, and sends the submit key (Enter or the Template's `submit` key) within 2 seconds of the paste only if the same PID and agent program still hold the foreground ([ADR 0035](../adr/0035-herdr-core-composer-sends-through-the-attach.md)). If a shell took over, Send writes one raw `0x03` (`Ctrl+C`): `bash`, `fish`, `dash`, and `zsh` are counted on to drop the pending paste (**no longer in the terminal**), whereas other shells and PowerShell show **may still be in the terminal**. After an unanswered Send step, the Composer offers **Edit Draft** instead of Retry, and the next Send waits for a Host read and warns that the previous message **may still be in the Agent's input**.
- **Composer Stop notices:** [HerdrCoreComposerStop](../../Sources/Heeler/Console/HerdrCoreComposerStop.swift) sends `terminal.interrupt` with a 2-second timeout and then reads the foreground ([ADR 0035](../adr/0035-herdr-core-composer-sends-through-the-attach.md)). Beside **still shows Working**, a dropped or silent connection produces **may or may not have reached the Agent**, an unanswered post-interrupt foreground read produces **did not say whether the Agent still runs**, and a call that never left the writer produces **wasn't sent**. Grok Build keeps **Send** during a turn because `Esc` does not stop its turns.
- **Another core at the same socket (`core.id` change):** If a different core process with a new `core.id` answers at the same socket path (for example under another `XDG_STATE_HOME`), any open Agent detail or Shell Terminal stays pinned to the old `core.id` (`TerminalCorePin`, `ConsoleDetailCores`). Its terminal shows as ended and states that it belongs to a core that is gone, an open Chat switches back to that ended terminal, and Close, Send, Stop, and Blocked answers are refused until the user reopens the row from the new core's list ([ADR 0031](../adr/0031-herdr-core-hosts-connect-without-starting-a-core.md)).
- **Launches and Templates:** `New Agent` passes session flags where supported (`--session-id` for Claude Code and Pi, `-s` for Grok Build, `-s ses_…` for OpenCode 2.1+, `--no-daemon` for Codex) unless the user's arguments already select a session ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)). On a Host where `zsh` is the login shell and `~/.zshrc` is absent, `zsh` opens its new-user wizard and the Agent waits behind it until answered in the terminal ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md)). Templates run the core's `sh -c <command>` directly without the user's login shell or session flags; an empty name defaults to the Template name or `<name>-2` when taken. A Template with a first message waits up to 35 seconds for the program's first status report, and the core skips typing the first message if the program has not reported after 30 seconds ([lab checklist](../guides/herdr-core-testing.md#new-agent-and-new-terminal)). An unrecognized program stays in **Terminals** until it reports a status.
- **Windows discovery, PowerShell launch, and staging details:** On native Windows, **New Agent** discovers and launches programs through Windows PowerShell (`powershell.exe`), so the Agent gets the Windows PowerShell profile rather than PowerShell 7's (`pwsh`) profile, and Windows PowerShell may not pass an argument containing a double quote or an empty argument whole to a program. A program installed behind an `fnm` junction may be refused over SSH exec (`ERROR_UNTRUSTED_MOUNT_POINT`) even though a core Terminal can run it ([herdr compatibility](herdr-compatibility.md)). Staged files in `%LOCALAPPDATA%\herdr-core\<session>\files\<terminal>\` inherit the user profile's ACL (`SYSTEM`, `Administrators`, and the user account on the tested machine) and are removed on `terminal.rm` or when the core prunes finished Terminal records after about 24 hours ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md)).
- **Worktree removal edge cases:** [HerdrCoreWorktrees](../../Sources/Heeler/Console/HerdrCoreWorktrees.swift) re-reads git status after ending the Workspace's Terminals; if uncommitted changes or initialized submodules appeared while the Terminals were ending, removal stops with the Terminals ended and the checkout preserved so the next confirmation can warn about them ([ADR 0032](../adr/0032-herdr-core-hosts-fill-the-console-models.md)). If another Workspace shares the same checkout path, the confirmation names it because its Terminals will continue running in the deleted directory. If the connection drops while **Worktree Details** or a Close confirmation is open, the result is shown as an alert over the Console.
- **Core Environment on Windows:** On native Windows, [HerdrCoreEnvironmentCheck](../../Sources/Heeler/Transport/HerdrCore/HerdrCoreEnvironmentCheck.swift) reads variable names from the core process's memory (`HostProcessReader+Windows.swift`). Because a failed read (such as across an elevation boundary) is silent, the absence of **Core Environment** on Windows does not prove the core's environment is clean ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)).

### Chat binding, OpenCode plugin edit, and platform limits

- **Manual conversation choice lifecycle (`HerdrCoreSessionBinder+Pick`):** A conversation selected with **Choose a Conversation** → **Use This Conversation** is shared across devices through the Terminal's label, and is dropped (returning Chat to **Can't Tell the Conversation**) when another process takes over the terminal, when the program names a session for itself or Chat finds exact evidence, or when a message confirmed sent from Chat is missing from the conversation after the Agent's next turn ends ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)). A transient process-read failure keeps the bound conversation under a banner and refuses Send until a check succeeds. **Choose a Conversation** is not offered on a native Windows core Host yet, and Codex on its shared background server offers `codex resume --no-daemon` instead of a candidate list.
- **OpenCode Chat and `Let Chat Follow OpenCode…` (`OpenCodePluginEdit`):** OpenCode is currently excluded from `confirmedLinuxCoreChatPrograms`, `confirmedMacOSCoreChatPrograms`, and `confirmedWindowsCoreChatPrograms` ([HostCapabilities](../../Sources/Heeler/Console/HostCapabilities.swift)), so OpenCode Agents offer the terminal only ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)). When enabled, **Let Chat Follow OpenCode…** writes `heeler-opencode` under `$XDG_CONFIG_HOME/opencode` or `~/.config/opencode` and adds `"./heeler-opencode"` to `plugin` in `tui.json(c)` (OpenCode 1.x) or `plugins` in `cli.json` (OpenCode 2.x), refusing 1.x files that have a nested `tui` key so a top-level `plugin` does not clobber it ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md), [lab checklist](../guides/herdr-core-testing.md#opencode-edit)). Without the plugin, OpenCode 2.1+ started from **New Agent** binds to its launch `-s ses_…` id and checks the terminal title before each Send; with `terminal.title` off or an untitled conversation, Send cannot detect an in-process `/new` or session switch. If `OPENCODE_DB` is set only in an interactive shell rc on a Host that also has the default database, Chat reads **No Messages Yet** and a Send from Chat times out with **Conversation Not Found** ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)).
- **Pi and Oh My Pi custom paths and title model:** [HerdrCoreSessionBinder+Pi](../../Sources/Heeler/Chat/Source/HerdrCoreSessionBinder+Pi.swift) resolves custom session folders from the Agent process's environment (`PI_CODING_AGENT_DIR` and `PI_CODING_AGENT_SESSION_DIR` for Pi; `PI_CONFIG_DIR`, `OMP_PROFILE`, `PI_PROFILE`, and `PI_CODING_AGENT_DIR` for Oh My Pi). It cannot see folders configured only via CLI flags or config files (`--session-dir`, `sessionDir`, `--profile`, `.env`, or `omp config init-xdg`) unless Heeler's extension is active. Without the extension, Oh My Pi opens its session file only after its title model replies (checked once more 10 seconds after a turn ends); if the title model returns nothing, it stays on **Can't Tell the Conversation** ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)).
- **macOS Apple binary wrappers:** On macOS with SIP enabled, `KERN_PROCARGS2` withholds environment variables for Apple platform binaries (`/bin/sh`, `/bin/zsh`). If an Agent is started as a child of a script that keeps an Apple shell running between the Terminal's foreground and the Agent, Heeler cannot read `HC_SCOPE` across the wrapper and shows **Can't Tell the Conversation** with no candidate list ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md), [herdr compatibility](herdr-compatibility.md)).
- **Windows process read and extension updates:** On native Windows, if herdr-core runs elevated while the SSH session does not, or if PowerShell runs in constrained language mode, `HostProcessReader` cannot read the Agent's process (`cannotReadProcessesOnWindows`), so Chat explains that and omits **Add Heeler's Extension…** ([ADR 0034](../adr/0034-herdr-core-chat-binds-sessions-from-host-evidence.md)). Updating Heeler does not overwrite an existing `heeler-session.js` on Windows while it still binds; deleting `heeler-session.js` from `.pi\agent\extensions` and `.omp\...\agent\extensions` and restarting the Agent prompts **Add Heeler's Extension…** again.

### Host Helper, Notifications, Live Activity, and Usage

- **macOS LaunchAgent checks and reboot reload:** On macOS, checking the **Host Helper** row takes about 11 seconds because [HostHelperInstaller](../../Sources/Heeler/Hosts/HostHelperInstaller.swift) samples `launchctl print` twice to distinguish a stable process from a crash loop ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md)). After a Mac restart, `user/<uid>` may not load the LaunchAgent until Heeler next checks the Host detail or connects from a device with notifications enabled, which bootstraps it again automatically. macOS may display a background-activity notice for `node` under Login Items.
- **Notification debounce, retry, and seen marks:** The Helper ignores statuses lasting under about 5 seconds, does not notify for state already present when it first connects to a core, and retries failed Push Relay deliveries for about 12 minutes while the state still holds ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md)). Per-device Done state is synced via `seen-<Notification Key id>.json` in the Helper directory.
- **Suspended Live Activity fields:** While Heeler is suspended, Live Activity updates sent by the Helper name each Agent's workspace from its checkout or launch folder rather than the Herdr desktop app's space name, and leave Tab or Pane row fields empty until Heeler returns to the foreground ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md), [Live Activity contract](live-activity-contract.md)).
- **Usage Default Account and macOS Keychain:** On a core Host, the **Default Account** follows variables (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`) read by name from the core process's environment rather than the SSH login's, and Usage queries the Helper over its own SSH exec even while the core is stopped. On macOS, Claude Code keeps its sign-in in the login keychain: in a macOS 26.5 virtual machine with a dummy credential, neither the Helper nor SSH could reach it, and on a Mac with Claude Code signed in, SSH could not either, and whether the Helper's own service can there has not been checked ([ADR 0033](../adr/0033-herdr-core-hosts-run-a-heeler-host-helper.md)). When they cannot, its **Usage Limits** read **need your own login on this Mac**, while Token Usage still counts.
